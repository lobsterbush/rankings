ARWU / ShanghaiRanking edition 2023
Source URL: https://www.shanghairanking.com/api/pub/v1/arwu/rank?version=2023
(public JSON API; discovered via https://github.com/ChalmersLibrary/ShanghaiRankingListsToCSV)
Method: Channel B WebFetch transcription of the JSON payload.
Every chunk fetched TWICE with differently-worded prompts; only rows where both agreed
exactly on rank_display + institution were kept.

Rows: 231 total = 100 exact-rank + 131 banded.
Disagreement rate on this pass: 0.00% (0/167).

COLUMNS
  rank_display  the ranking field copied VERBATIM from the API ("57" or "101-150")
  rank_low/high band edges parsed from rank_display (equal to each other when not a band)
  is_band       1 if the source gave a band rather than an exact rank
  total_score   published only for exact ranks; empty/null for banded institutions

IMPORTANT ON BANDS
ARWU publishes exact ranks only to 100; below that institutions are grouped into bands and
listed ALPHABETICALLY within each band, with no per-institution rank or score. Band membership
here was established two ways and both agree:
  (a) the alphabetical sequence restarts at each band boundary in the raw payload, and
  (b) targeted single-institution lookups on the boundary names were run twice with different
      wording and returned the same band string.
No band label was inferred from position alone.

TRANSCRIPTION FAULT FOUND AND WORKED AROUND
Asking the fetch model for 'elements whose ranking is exactly "151-200"' made it return the
101-150 band as well and stamp the requested label onto every row. Positional requests
("elements 151-200 of the array") failed the same way. Only explicit-exclusion prompts
("output the 151-200 band, exclude everything in 101-150") returned clean bands. Any future
pass over this API should use the exclusion phrasing and verify boundary names.

COVERAGE LIMIT
WebFetch truncates this payload partway through the 201-300 band, so the file stops there.
Ranks beyond ~300 (bands 301-400 ... 901-1000) are NOT captured and cannot be reached through
this channel. A client that can stream the full ~1 MB JSON would get all 1,000.

--- scimago/NOTES.txt
SCImago Institutions Rankings - editions obtained 2026-08-12
============================================================
CHANNEL: Channel B, but the BEST sub-case of it - the documented bulk CSV endpoint
  https://www.scimagoir.com/getdata.php?ranking=Overall&area=&sector=Higher%20educ.&country=&year=YYYY&top=300&format=csv&type=download
WebFetch returns this endpoint's payload verbatim (semicolon-delimited), so this is a raw
file download surfaced through WebFetch, not a small-model transcription of a rendered table.

FILES (all sector=Higher educ., i.e. universities only; top 300 per edition):
  COMPLETE ANNUAL SERIES 2009-2019 + latest edition.  12 files, 3602 rows total.
  scimago_2009_higher-educ_top300.csv   300 rows  5 cols
  scimago_2010_higher-educ_top300.csv   300 rows  5 cols
  scimago_2011_higher-educ_top300.csv   301 rows  5 cols  (tie at rank 300 -> 301 rows)
  scimago_2012_higher-educ_top300.csv   300 rows  5 cols
  scimago_2013_higher-educ_top300.csv   300 rows  5 cols
  scimago_2014_higher-educ_top300.csv   300 rows  5 cols
  scimago_2015_higher-educ_top300.csv   300 rows  5 cols
  scimago_2016_higher-educ_top300.csv   301 rows  5 cols  (tie at rank 300 -> 301 rows)
  scimago_2017_higher-educ_top300.csv   300 rows  5 cols  (last rank is 299, tie at 299)
  scimago_2018_higher-educ_top300.csv   300 rows  5 cols
  scimago_2019_higher-educ_top300.csv   300 rows  5 cols
  scimago_2024_higher-educ_top300.csv   300 rows  6 cols  (= LATEST edition, see caveat)
  NOTE: the endpoint returns all members of a tie group, so top=300 can yield 301 rows.
Columns 2009/2014/2019: Rank;Global Rank;Institution;Country;Sector
Columns 2024:           Rank;Global Rank;Institution;Country;Sector;Best Country Quartile
  "Rank"        = rank within the Higher educ. sector
  "Global Rank" = rank across ALL sectors (govt, health, companies, non-profit included)
  A trailing " *" on an institution name is SCImago's own marker, kept verbatim.
  No overall composite score is exposed by this endpoint in any year.

*** IMPORTANT CAVEAT ON THE YEAR PARAMETER ***
The endpoint only serves DISTINCT archived editions for year=2009..2019.
Any year >= 2020 returns the current/latest edition. Verified: year=2020, 2021, 2022,
2023, 2025, 2026 and even the nonsense year=2099 all return byte-identical payloads.
So the file labelled 2024 is really "the latest edition the endpoint serves"; its true
edition year is NOT established by the endpoint. 2025 and 2026 editions were NOT obtained
as separate editions and no separate files were created for them - that would have been
duplicate data masquerading as new years.

VERIFICATION / disagreement rate:
 1. year=2023 and year=2024 were fetched as separate URLs with differently-worded prompts.
    Both returned identical 300-row payloads: 0/300 rows disagreed on rank+institution.
    (They are the same edition - see caveat - which is exactly why this is a clean
    duplicate-transcription test.)
 2. 2009 was re-fetched a second time with a different URL and a different prompt style
    ("reproduce rows 1,2,3,50,100,150,200,250,299,300"). 9/10 spot rows matched exactly.
    The single mismatch (row 50) was then adjudicated with a third contiguous-range fetch
    (top=55, "last 12 lines"), which confirmed the ORIGINAL file is correct
    (49=Karolinska Institute/73, 50=Universitat Heidelberg/74). The verification fetch had
    blended adjacent rows. Net disagreement on the primary transcriptions: 0/10.
    LESSON: contiguous-range prompts are reliable; "pick out row N" prompts are not.
 2b. Second pass used ONLY contiguous-range prompts, per that lesson. 2012 was re-fetched
    independently (top=55, "last 12 lines") and compared to the saved file:
    0/11 rows disagreed on rank + institution + country.
 3. Structural QA on all 4 files: exactly 300 data rows each, rank monotonic
    non-decreasing 1..300 (ties present, as in source), 0 duplicate institution names,
    0 blank names, leader = Harvard University in every year (plausible for SCImago
    higher-ed sector; the all-sector list is topped by Chinese Academy of Sciences etc.).

FRACTION OF EACH EDITION CAPTURED: top 300 universities only. A full higher-educ edition
is roughly 4000-8000 institutions, so this is very roughly the top 4-8%. The endpoint
truncates at ~1680 lines through WebFetch (top=0 was cut off mid-row at line 1681), so
full editions are not retrievable in one call; they would need country-by-country
partitioning via the &country= parameter.

2026-08-12 SECOND PASS: years 2010-2013 and 2015-2018 were added, completing the annual
series. Each was a single call of the same form. All 12 files re-validated together:
ranks monotonic non-decreasing in every file, no ragged rows, no blank institution names,
no duplicate institution names within a year, and Harvard University is rank 1 in all 12.
Cross-year check: 198 institutions appear in ALL 12 editions -> a usable balanced panel.

STILL MISSING: ranks 301+ for every year (depth was not extended; the &country= partition
approach was not attempted), and any genuine 2025/2026 edition (the endpoint does not
serve one - see caveat above).
